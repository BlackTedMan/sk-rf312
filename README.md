# СК РП — сервер базы дел (фундамент)

Backend на FastAPI + SQLAlchemy (SQLite). Отвечает за регистрацию/вход игроков,
хранение дел по отделам и live-уведомления о новых делах через WebSocket.

## Запуск (рекомендуемый способ — без сборки в exe)

Сервер должен просто постоянно работать на одном компьютере/VPS — собирать
его в exe не обязательно и часто лишняя головная боль (см. ниже). Проще
всего на Windows дважды кликнуть **`start_server.bat`** — он сам поставит
зависимости при первом запуске и поднимет сервер на `http://localhost:8000`.

Вручную (любая ОС):

```bash
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # Linux/Mac

pip install -r requirements.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

После запуска:
- Документация API (можно тестировать прямо в браузере): http://localhost:8000/docs
- WebSocket для live-обновлений: ws://localhost:8000/ws

При первом запуске база `sk_app.db` создаётся автоматически и засеивается
отделами + категориями дел УПРДЛ (по данным, которые вы дали). Остальные
отделы (УСБ, УПК, УПОВД, ООСБ, ФГГС, УК, Руководство) созданы как заготовки
без категорий — добавьте их категории запросом:

```
POST /departments/categories
{
  "department_id": 2,
  "name": "Название категории",
  "is_archive": false
}
```
(нужны права администратора — см. ниже)

## Как сделать первого администратора

Сначала зарегистрируйтесь как обычный пользователь через `POST /auth/register`,
затем в базе `sk_app.db` вручную поставьте `is_admin = 1` этому пользователю
(через DB Browser for SQLite или `sqlite3 sk_app.db "UPDATE users SET is_admin=1 WHERE username='...';"`).
Дальше он сможет создавать категории и т.д. Роли/права можно расширить под
структуру отделов, когда пришлёте детали по остальным.

## Что уже есть

- Регистрация/вход (JWT) с полями: логин, ФИО, должность, отдел
- Отделы и категории дел (справочники, расширяемые)
- Дела: создание, список, фильтр по отделу/категории/статусу, обновление,
  закрытие (статус "закончено расследование" = архив), доказательства (файлы/ссылки)
- Лог активности (кто и что делал) — основа для автохарактеристики
- `GET /users/{id}/characteristic?period_days=30` — автогенерация текста
  характеристики на основе активности за период
- WebSocket `/ws` — рассылка событий `new_case`, `case_updated`, `case_closed`
  всем подключённым клиентам в реальном времени

## Бесплатный хостинг сервера онлайн (чтобы не держать свой ПК включённым)

Вместо запуска на своём компьютере, сервер можно бесплатно разместить на
**[Render.com](https://render.com)** — так он будет доступен всем игрокам
постоянно по ссылке вида `https://sk-server-xxxx.onrender.com`, без
привязки банковской карты.

Шаги:

1. Загрузите папку `sk-server` в свой репозиторий на **GitHub** (Render
   деплоит именно из Git-репозитория — если аккаунта на GitHub нет,
   создайте бесплатно на github.com и загрузите файлы через веб-интерфейс
   "Add file → Upload files").
2. Зарегистрируйтесь на render.com (можно через GitHub-аккаунт).
3. New → Blueprint → выберите ваш репозиторий. Render сам прочитает
   `render.yaml` из этой папки и создаст веб-сервис **и** бесплатную
   PostgreSQL-базу, подключив их друг к другу автоматически.
4. Дождитесь деплоя (несколько минут) — в панели Render появится ссылка
   вида `https://sk-server-xxxx.onrender.com`.
5. В клиенте (`sk-client/client/config.py`) пропишите эту ссылку в
   `SERVER_URL` — и пересоберите/перезапустите клиент. Discord-бот (когда
   дойдём до него) будет ходить на ту же ссылку.

Важно:
- Бесплатный веб-сервис Render "засыпает" после ~15 минут без запросов —
  первое обращение после паузы грузится 30–60 секунд, дальше работает
  быстро. Для фракции это обычно некритично.
- База теперь через `DATABASE_URL` (Render передаёт её автоматически) —
  локально при запуске на своём ПК всё так же используется SQLite
  из коробки, ничего вручную менять не нужно.

## Сборка сервера в exe (необязательно)

Если всё же хочется отдельный `.exe` вместо `start_server.bat` — на Windows
выполните `build_server.bat`. Готовый файл — `dist\SK-Server.exe`, база
`sk_app.db` создастся рядом с ним при первом запуске.

Раньше здесь использовались `passlib` и `python-jose` — они полагаются на
динамические импорты по строкам, которые PyInstaller не всегда видит
статически, из-за чего вылезали ошибки вида `ModuleNotFoundError:
No module named 'passlib.handlers.bcrypt'`. Сейчас вместо них — `bcrypt` и
`PyJWT` напрямую, они собираются в exe без таких сюрпризов. Если всё же
всплывёт `ModuleNotFoundError` на каком-то другом модуле — допишите
`--hidden-import=<имя_модуля>` в команду `pyinstaller` внутри
`build_server.bat` и пересоберите.
